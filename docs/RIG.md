# 骨骼绑定规范（防错位、防漂移）

以前出问题的根源通常有三个：零件来自不同的图、比例和坐标对不上；关节转轴放错位置；动画里移动了不该移动的骨骼，导致脚底打滑。下面每条规则对应一个根源。

## 1. 统一坐标系：所有零件出自同一张母版
- 主体零件（头发、头、躯干、手臂、腿、鞋）**全部从同一张母版上切**（`master_armout.png`），保留各自在母版上的原始像素坐标。
- 每个零件的附件位置 = 它在母版上的中心点，换算到所属骨骼的局部坐标。这样**初始姿势（setup pose）拼起来必然和母版一模一样**。
- 单独生成的道具图（握召唤器的手、剑）比例不一定一致：先在母版上量出前臂袖口宽度，按它缩放道具图，再按袖口位置对齐，最后用叠图检查。

## 2. 自动校验（每次生成骨骼都必须通过，不通过不交给 Codex）
`tools/rig/` 里有一个最小 Spine 求值器，和游戏用同样的矩阵规则计算骨骼世界变换并渲染：
1. **拼合校验**：渲染初始姿势，和母版逐像素比较，差异超过阈值就报错。
2. **关节校验**：每个动画的每一帧都检查父子零件在关节处有没有裂缝（关节两侧的轮廓距离）。
3. **脚底校验**：站立类动画中，每帧计算鞋底接触点的世界坐标，漂移超过 2px 就报错。
4. **预览**：每个动画导出一张 GIF，推到仓库 `art/rig_preview/`，你可以在 GitHub 上直接看。

## 3. 关节与切割
- 转轴放在解剖学关节中心：肩、肘、腕、髋、膝、踝、颈。
- 切割时每个零件在关节处**多留 12~20px 的重叠**，并把重叠边缘做成圆弧。这样零件绕关节旋转时不会露缝。
- 图层顺序固定：远侧腿 → 远侧手臂 → 躯干 → 近侧腿 → 头发后片 → 头 → 刘海 → 耳机 → 近侧手臂 → 武器。

## 4. 动画规则（防漂移）
- 四肢只用**旋转**，不用位移。
- 唯一允许位移的是根骨骼和髋部骨骼（重心起伏、后仰）。
- 髋部移动时，腿部旋转用**两段式 IK 解析**反算，保证鞋底位置固定不动；结果直接烘焙成关键帧，不依赖运行时 IK。
- 所有循环动画（idle_loop 等）首尾帧完全相同，避免循环接缝跳动。
- 关键帧按 30fps 烘焙为线性插值，预览渲染器和游戏看到的是同一组数据。

## 5. 兼容约定（原版代码依赖，见 DESIGN.md 2.2）
动画名、`*_particle_attach` 骨骼、`shadow` 插槽、die 动画中的 4 个事件，全部保留。

## 6. v2 改进（游戏内反馈：偏小、手像拼上去的、动作塑料）
- 比例 K 0.77 → 1.0。
- **手臂网格变形**：肩帽到手腕是一张加权网格；肩部顶点在躯干↔上臂之间、肘部顶点在上臂↔前臂之间线性分配权重，弯曲时像布料一样平滑，没有硬接缝。手和袖口的接缝做 10px alpha 渐变。
- **二阶弹簧动力学**：每个关节通道追赶目标姿势（`DYN` 表：越靠末端频率越低、阻尼越小），自动产生滞后、跟随与过冲回弹；攻击 / 施法用更高速度系数保持干脆。
- **动画事件**：`weapon_draw / weapon_slash / weapon_sheath / evoker_draw / evoker_fire / evoker_sheath`，游戏端按事件在精确帧上触发武器显现、挥砍拖尾、消散、召唤器发动。

## 7. v3：姿势专用手绘手臂（sprite swap）
母版手臂透视缩短，2D 旋转做不出"手肘外展、前臂折回、手腕侧转"的举枪姿势，也做不好自然下垂。
- `arm_hanging`（骨骼 `arm_hang`）：待机 / 受伤 / 死亡时的手臂。
- `arm_raised_evoker`（骨骼 `arm_raised`，子骨骼 `muzzle` / `grip`）：枪抵太阳穴时的手臂；两点定位（肩点 + 枪口对太阳穴）对齐。
- 网格手臂只用于过渡（亮枪、抬起途中）和挥剑。
- 状态切换用插槽 rgba 交叉淡化 0.04s，发生在快速运动中（`ARM_STATES` / `arm_slots`）。

## 8. 预备出牌的过渡（v0.3.3）
- 拖牌：`aim_in` / `sword_in`（下沉蓄力 → 弧线抬起 → 过冲回稳）后接循环。
- 取消：`aim_out` / `sword_out`（停顿松劲 → 顺重力放下 → 轻晃停住），武器消散由其中的 sheath 事件触发。
- 打出：`AnimRenamePatch` 在游戏请求 cast / attack 时，若角色处于预备姿势，换成 `cast_from_aim` / `attack_from_ready`，直接接招。
- 校验第 5 项：相接动画接缝处骨骼差 ≤ 6（当前全部 ≤ 2.2）。

## 9. v4：近侧右臂 + 姿势手绘手臂（当前版本，`tools/rig/build_rig_v4.py`）
**修正的解剖错误**：v1~v3 用远侧左臂（戴臂章）做动作，并把它画在躯干前面。3/4 侧身朝右时近侧是右臂（画面左侧）。
P3 原作右手持召唤器抵近侧太阳穴。v4 身体用 `art/v4/body_cut.png`（去掉右臂），左手插兜，右臂 6 张手绘姿势。
- 每张手臂一根骨骼（`rarm_*`，torso 子骨骼，轴心在右肩）；状态切换 = 插槽 rgba 交叉淡化。
- **方向对齐**：隐藏的手臂始终转到与当前手臂"手的方向"一致（`THETA`），切换 A→B 时 B 从 A 的方向转回自身姿势 —— 画面上是一条手臂连续扫过。
- 伸展程度差别大的两张手臂之间淡化 ≥0.1s（手臂收拢 / 伸出的观感）。
- **特效锚点** `hand / grip / muzzle / evoker_tip / sword_tip` 是 root 子骨骼，每帧按手臂透明度加权烘焙到当前显示的道具位置；
  道具未显示时跟随手。`grip` 取枪管后端，`muzzle - grip` = 枪管方向。
- 校验新增：锚点**径向**连续（锚点到肩距离的单帧跳变：手 ≤80、枪口 ≤90、剑尖 ≤160；只统计道具完整显示的帧）。

## 10. 打击跟手（v0.5.0）
游戏在触发 Attack 后 **0.15s**（快速模式 0.075s）就结算伤害、跳数字、播命中特效（`CreatureCmd.TriggerAnim` 的等待）。
v0.4 的刀在 0.26s 才落下 —— 先跳伤害后挥刀，所以"不跟手"。
- 接触帧（刀扫到水平指向敌人）提前到 **≈0.09s**（attack）/ **≈0.07s**（attack_from_ready）：蓄力只有 1~2 帧，拖牌时的 `ready_sword_loop` 本身就是蓄力。
- 斩下段用加速缓动（`CUT = u³`，接触瞬间速度最大），弹簧速度 3.0；之后余势停顿、慢收剑（快出慢收）。
- 举剑 → 斩下两张手绘之间剑尖一帧扫过（拖影帧），攻击动画剑尖径向上限放宽到 300。
- 命中：顿帧 50ms + 轻震屏，落在接触帧之后约 1~2 帧。音效除召唤器枪声外全部用游戏原版。

## 11. 锚点必须落在画上（v0.5.0）
v0.4 召唤器手臂的枪口坐标量错（落在空白处），两点对齐把真正的枪口放到了脖子。校验新增：每个锚点 8px 范围内必须有不透明像素。

## 12. 召唤器只留给大招（v0.5.0）
召唤器（抵太阳穴开枪）只用于**召唤 Persona 的牌** —— 以 `CardStyles.Captions`（色带字幕表）为准，约 15 张。
其他游戏会播 Cast / PowerUp 的牌：`CardFx.OnPlay` 标记 `Pose.MarkLightCast`，`AnimRenamePatch` 把这次的 `cast` 换成 `cast_light`
（吸气后仰、抬头、垂手前摆，0.75s，不换手臂），拖牌时也不做预备姿势；能力牌保留光柱 / 塔罗演出但不开枪。
