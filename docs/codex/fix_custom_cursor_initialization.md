# 部分玩家仍显示原版光标：防御性加固

用户反馈有玩家其他功能正常，鼠标没有换肤；没有对方的日志、确切版本、平台或 mod 列表，尚不能确定根因。

已确认：旧代码只在 NCursorManager._EnterTree 的 Prefix 中替换一次；图片读取返回 null 时不记录原因，也没有晚加载补应用。两张实际图片都是 64×64 RGBA，已在现有 PCK 中。旧注释的 48×48 已更正。0.107.1 与 0.111.0 中两个默认图片字段和 UpdateCursor 方法仍存在，未发现这两个版本的字段改名。

修正：

- 原 _EnterTree 补丁保留；增加原版 UpdateCursor 前的一次性检查，并在 mod 初始化后的 deferred 回调扫描已存在的管理器，补救节点早于补丁初始化的情况。
- 每个管理器成功应用后不再重复读图/写字段，不逐帧与其他 mod 抢光标；保留原版查看光标、临时覆盖、按下倾斜和手柄隐藏逻辑。
- 强引用持有普通、按下两张 Image；检查解压结果和硬件光标尺寸/热点范围，转换为 RGBA8。贴图读取失败时尝试包内原始 PNG，不额外下载或改变资源文件。
- 失败明确记原因，最多尝试三次，每次至少隔一秒；定时补救前确认节点仍有效且在树中。成功记录 `cursor skin applied: 64x64, hotspot=(14,5)`；仍失败保留原版，不阻止游戏启动。

验证：Release 0 警告、0 错误；0.107.1 / 0.111.0 ApiCheck 均通过（P3Makoto 935 处引用），并只读核对两版光标管理器字段及刷新逻辑。未启动游戏，不能宣称已复现或必然修复那位玩家的问题。

若仍异常，请收集该玩家 godot.log 中含 `cursor`、`P3Makoto` 的相关行，连同游戏/mod 版本与其他已启用 mod 列表。若日志显示成功但仍是原版样式，继续调查其他 mod 覆盖、特殊光标状态或系统显示行为。
