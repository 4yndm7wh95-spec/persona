# 牌堆翻转削边与牌组默认显示升级预览

基线 `ec34ce8`，版本清单仍为 v0.14.76。本次只修改 `mod/src/Vfx/PileFx.cs` 的显示逻辑，不改真实卡牌、存档或美术素材。

## 翻转时费用圆标和标题飘带被削边

翻转替身先把 `NCard` 渲染进 `SubViewport`，再将纹理贴到透视网格。旧画布的大小直接使用 `holder.Hitbox.Size`；命中框只覆盖主体矩形，而费用圆标、标题飘带的左右尖角会伸出这个矩形。正常静止卡牌能画出这些部分，只有切换成离屏翻转替身时被截掉，与截图一致。

修改：

1. 在离屏画布四边各增加 48 个卡牌局部单位的透明留边；仍保持 1.5 倍渲染分辨率。
2. 把离屏卡牌中心移到扩展后画布的中心，保持卡牌图像在原转轴上。
3. 正面透视网格同步扩展到包含透明留边，整张离屏纹理一比一映射到对应的局部范围。仅放大画布、不改映射会把主体缩小，因此两处必须一起修改。
4. 背面继续使用原主体尺寸；相机距离、外层缩放和转轴也继续按原主体尺寸计算，避免正反面尺寸突然改变。

这个通用翻转路径覆盖抽牌堆、弃牌堆、消耗堆、牌组的飞入/飞回特写和「查看升级」翻转。

## 未勾选查看升级，牌组却全部显示绿色升级样式

只读检查 0.111.0 和 0.107.1 的原版流程：

- `NTickbox._isTicked` 默认是 `true`。
- 我们在 `NDeckViewScreen._Ready` 后搭建界面，旧实现立刻读取了这个默认值，保存到 `upgradeOn`。
- 原版稍后在 `NCardsViewScreen.AfterCapstoneOpened()` 中直接设置 `_showUpgrades.IsTicked = false`。
- 直接写属性只更新勾选图案，不发 `Toggled` 事件；旧实现只监听事件，因此缓存仍是 true，随后分批创建的自定义卡牌全显示升级预览。
- 其他三个牌堆没有这个全局勾选框，`upgradeOn` 保持 false，所以正常。

这次定位到的主因是初始化时序，不能误报为真实牌被升级，或仅归为对象池问题。

修改：

1. 不再于 `_Ready` 读取默认 true，也不只依赖 `Toggled`。
2. 每帧在分批建牌之前读取实际 `IsTicked`，只在值改变时刷新现有网格；无须每帧重建卡牌。
3. 新建 holder 时明确应用 true 或 false，避免只在启用时写入。
4. 已聚焦的单张卡保留自己的升级翻转状态；收回时仍按最新网格勾选值恢复。全局勾选和单卡预览不改变原 `CardModel`，升级预览使用既有克隆流程。

## 用户复验

- 新开牌组界面，不勾「查看升级」：未升级的打击/防御保持普通名称、数值，确实升级过的牌仍显示真实升级状态。
- 勾选/取消、手柄与鼠标切换、关闭后重开，以及切换不同牌堆，显示都与勾选框和真实卡牌一致。
- 放大君王之剑等费用圆标和飘带突出的牌，反复飞入/返回、翻转升级预览：三处凸出装饰应保持完整，正反面主体尺寸不跳变。
- 实际出牌数值不受预览切换影响。
