你在用户的 Windows 电脑上工作。任务：用 imagegen 给 P5 Joker 局内动作**画过渡帧（中间帧）**，一共 10 组、19 张。只做美术，不改代码，不启动游戏，不用 Computer Use。

找仓库、拉取（git fetch + merge，能快进就 --ff-only）、提交推送、「绝对不要做」清单都和 docs/codex/codex_p5r_model_fix.md 一样，另外沿用 docs/codex/codex_p5_poses4.md 开头的全部禁止事项（不改代码、不 rebase / reset / amend / --force、不改全局 git config、不动 sparse-checkout、不读 obs.json 和密码、不碰 P3Makoto 的图、不改游戏原文件、不绕过 imagegen 的安全拒绝）。
分支：`claude/character-animation-smoothness-dearur`。遇到没写到的情况，停下来报告。

【0. 背景】
- 用户反馈 Joker 局内动作不顺。Joker 的每个动作是若干张整身姿势图轮流切换，以前每次换图都是硬切。
- 现在每次换图之间会自动插 1~2 张过渡帧（tools/p5/tween.py，用光流把上一张图的像素"推"到下一张图的位置）。
  大部分效果不错，但**身体整体大幅移位、手臂大幅甩动**的几组会出现重影（两只手 / 两个身体叠在一起），需要手绘的中间帧代替。
- 你画好的图放进 `art/p5/poses/tween_override/`，构建脚本会自动用它代替自动生成的那张，不需要改任何代码。

【1. 每张图的统一要求】
- **输入 = 起点那张定稿图** `art/p5/poses/final/<起点>.png`（1536×1632，透明底，已经和待机图对齐过），做图像编辑；
  **终点那张定稿图** `art/p5/poses/final/<终点>.png` 作为第二张参考（只看姿势，不是编辑对象）。
- 只把动作从起点往终点挪到指定的百分比（33% = 走了三分之一，67% = 走了三分之二，50% = 一半）。
  人物、服装、比例、画风、脸都和起点图一致；不加任何特效、拖影线、速度线。
- 参考 `art/p5/ref/tween_req/<起点>__<终点>.png`：从左到右是 起点 / 现在自动生成的过渡帧（就是要被替换掉的那张，**只用来看位置大概在哪，重影不要照着画**）/ 终点。
- **画布必须是 1536×1632、真透明底，人物位置和起点图对齐**：
  - 站姿：鞋底和起点图在同一高度；没移动的那只脚，像素位置和起点图一致（误差 ≤ 4px）。
  - 倒地那 3 组（die_*）：身体最低点贴地，地面线和起点图一致（倒地本身会往前移，不要求脚对齐）。
  - imagegen 出不了 1536×1632 时：生成 1024×1088（同比例），再**精确放大 1.5 倍**到 1536×1632，然后按上面的要求平移对齐；不要拉伸变形。
- 每张清理残点：主体外扩 16px 以外、alpha ≤ 2 的像素置 0。
- 同一组有两张（33% 和 67%）时，**先画 33%，再以 33% 那张为输入画 67%**，保证两张连贯。
- 一张通过了再做下一张；连续 3 次做不对就停下来，报告是哪张、问题是什么。

【2. 文件名】
`art/p5/poses/tween_override/<起点>__<终点>__<百分比>.png`，百分比两位数（33 / 50 / 67），例如 `die_kneel_a2__die_fall_a__33.png`。
名字必须和下表一字不差（起点、终点的顺序不能反）。

【4. 自检（每张都做）】
- 用 Python 把成品和起点、终点三张图半透明叠在一起（各 33% 不透明度），存到本机中间目录看：
  没动的部位（脚、没参与动作的那只手、外套下摆）和起点图重合；动的部位位置介于起点和终点之间、接近要求的百分比。
- 缩小到 25% 时轮廓清楚，没有两只手 / 两把刀。
- 持刀 / 持枪 / 扯手套用的是哪只手，和起点、终点一致。
