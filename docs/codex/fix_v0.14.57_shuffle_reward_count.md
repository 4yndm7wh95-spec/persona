# v0.14.57：Shuffle Time 按实际奖励张数布局与发牌

## 玩家报告

“吃不完的糖”遗物增加一张能力牌奖励后，四张奖励牌左右出屏，画面中央还有导航箭头。需求：有几张实际奖励牌，就给几张播放入场、落定、翻牌，完整显示并可选。

## 代码检查结论

旧实现并非所有地方都写死三张：Deal 的动画循环本来依赖 n。但是 n 来自 CardRow.GetChildren().OfType<Control>()，其中非卡牌控件也可能被当牌隐藏、排序和动画；布局仍使用固定 350 本地间距，没有视口宽度约束。截图含导航箭头，可能还涉及其他 mod 或宿主的布局行为，无法单凭截图断言是哪一个组件创建它们。

本修改解决我们自己负责的计数、定位、宽度和动画时序，不拦截遗物、不改奖励内容、稀有度、选择结果或数量；不删除其他 mod 的导航控件，不声称已复现玩家的完整 mod 组合。

## 整体方案

1. 只收集真正的 NGridCardHolder，排除排队删除的节点。导航控件不参与隐藏、发牌、翻牌、选牌后的退场。
2. 按实际数量计算一整行的占宽，以视口中线居中；默认三张、四张可容纳时保留正常大小，放不下才等比缩整行。预留两侧 6% 和悬停牌宽。
3. 缩放对象是本界面拥有的 CardRow；不修改对象池卡牌的 SmallScale、Hitbox、MouseFilter。原版悬停放大和命中区域一起随父级缩放，避免“画面缩小但命中框没变”。
4. 保存该行原始 Scale，每轮重抽先恢复原始值再计算；三张→四张→三张不会累积缩小。每张卡的落点和塔罗牌背的落点使用同一个更新后的全局变换。
5. 每张实际奖励牌各生成一个牌背和两道拖影；最后一张落定后统一翻面。数量多时压缩逐张间隔，使总入场仍在原有安全显示时间内。
6. 旧动画回调同时检查发牌轮次和入场 token；新一轮开始就不能用旧回调修改已复用的牌，翻面展开的补间也做相同检查。
7. 水圆背景水平中心与新卡牌行一致。没有牌背资源时仍直接显示真实牌，零张不除零。选择、跳过、键盘/手柄导航仍由游戏处理。

- mod/src/Core/ShuffleLayout.cs：无 Godot 依赖的数量/宽度/时序计算。
- mod/src/Vfx/StageFx.cs：真实卡牌枚举、整行适配、坐标共享、动画 token、逐张节奏。
- mod/src/Patches/StagePatches.cs：背景水平居中。
- mod/P3Makoto.json、mod/src/ModEntry.cs：0.14.57。
- tools/compat/ShuffleLayoutTests：直接编译生产布局类的独立控制台测试；不需要游戏、NuGet 测试框架或安装新运行时。

## 验证结果

- Release 编译：0 Warning(s)、0 Error(s)。
- 布局/时序自动测试：960 组（1～32 张 × 5 种视口宽度 × 3 种父变换 × 2 种牌宽），检查两侧完整、居中、不放大、正常翻牌早于兜底；另测零张、默认三张、四张全尺寸和第四张参与时间计算，全部通过。
- 运行命令：dotnet run -c Release --project tools/compat/ShuffleLayoutTests。
- 本机只有 .NET 10 运行时，测试工具与 ApiCheck 一样声明 RollForward=Major；游戏 DLL 仍以 net9.0 构建。
- 两版本 ApiCheck：P3Makoto 910、P3MusicBox 241、P3TestMod 382 处引用，StS2 v0.111.0 和 v0.107.1 均“结果：全部能找到 ✓”。
- 此补丁无资源改动，继续使用已验证的 P3Makoto.pck（75,347,716 字节，90 个 ogg）。
- 未启动 StS2 或进行游戏内操作；上述测试不等于遗物奖励界面、其他 mod 的布局补丁或快速重抽的完整集成验证。

## 用户验证步骤

1. 完全退出重开，日志应为 init v0.14.57；此版包含 v0.14.56 的鼠标对象池修复。
2. 无遗物三张奖励：标题→三张牌背依次落定→三张一起翻开，悬停、选择、跳过正常。
3. 带“吃不完的糖”触发四张奖励：四张都完整可见、均有牌背动画、逐张可选，额外能力牌不丢失。
4. 有其他加奖励数量来源时再测五张/更多；改变窗口尺寸后重新打开查看。
5. 重抽时测试三→四→三；动画中快速重抽、关闭后再开奖励，不得残留旧牌/提前翻面/缩小累积。
6. 右键检查、返回、手柄导航及关闭 Shuffle Time 后的原版行为仍应正常。
7. 如果相同 mod 组合仍有箭头强制分页或后续挪动卡牌，提供新版日志及 mod 列表；当前没有安装那位玩家的完整 mod 组合，不应直接改第三方代码。
