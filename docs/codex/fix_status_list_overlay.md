# 状态列表：白条、浅色背景、关闭与跨界面残留

基线：`28fa02c`（v0.14.76 的状态按钮位置修正）。最终需求仍是按钮常显；本次不加延迟隐藏。

## 根因

1. 左侧白条来自 `TipList.Backdrop` 的入场 `Wipe`。背景尺寸改变时，旧节点用 `QueueFree()` 延迟到帧末删除，同一帧又创建同名 `Wipe`。Godot 会给新节点改名，随后 `GetNode("Wipe")` 操作的仍是待删除旧节点。新扫光留在默认 `(0,0)`、保持可见，因此在画面左边留下白色斜条。
2. 整体半透明背景是 `Backdrop` 主动绘制的条带、斜纹、水印和气泡；选中行后面还叠有白色底板，并非游戏场景本身。
3. 原列表只能靠原按钮关闭；列表滚轮接收区域可能盖住按钮，而列表接收层又不处理关闭点击，因此会出现按钮看得见却点不到的情况。
4. 原列表挂在 `NGame.HoverTipsContainer` 全局提示层。`Stage.MakotoCombat()` 只检查战斗房间单例和本机角色；打开牌堆、地图、设置时，战斗房间可以继续存在，原条件不能判断前台是否仍是战斗。

## 修改步骤

- 删除整个 `Backdrop`（包括扫光、浅色整体底板、装饰水印/气泡），避免无用背景继续绘制。选中行去掉白色填充，保留深色文字底板、红框和指示箭头。
- 列表改挂在当前战斗的 `Ui` 下，用独立画布坐标定位；不再借用全局提示层。
- 在列表命中区域后增加无绘制的透明点击层。左键点击列表外空白处关闭，这次点击被消费，不穿透成出牌或攻击。
- 列表范围覆盖原按钮时，在命中层识别按钮矩形并执行关闭；文字说明及其子控件只绘制、不抢走滚轮/点击。
- 新增统一的 `CanShow` 条件：设置启用、储君战斗、战斗进行中、角色有效/存活/可见、属于当前房间，且 `ActiveScreenContext.IsCurrent(room)` 为真。按钮和列表共用条件。
- 监听原版 `ActiveScreenContext.Updated`：打开牌堆、地图、暂停/设置或其他上层界面时，立即隐藏并释放列表；每帧还复查一次，兜底处理没有发通知的切换。返回战斗不自动重新打开。
- 释放时解除屏幕事件、角色退出事件和帧事件，先 `Hide()` 再 `QueueFree()`，避免残留一帧和反复开关造成的事件引用累积。

## 用户复验

1. 状态较多时反复打开、滚动、关闭列表：左边没有白条，列表没有整块浅色背景。
2. 点击列表外空白处关闭；点原状态按钮也能关闭；这次关闭点击不能同时打出手牌。
3. 保持列表打开，用快捷键打开抽牌堆/弃牌堆/消耗堆/牌组、地图、暂停和设置：列表应立即消失。返回战斗后保持关闭。
4. 战斗结束或退出房间后没有列表残留；其他角色仍用原版。
