# 2026-10-23：玩家界面反馈调查（0.15.01 修订）

## 角色介绍板消失：根因明确，修复把握高

读取了用户提供的两个 7z 中的日志、截图、说明和 SkinAlphaGuard 的反编译代码；没有执行玩家附带的 DLL，也没有将其装入游戏。附件中的 AI 分析作为线索，结论以实际日志和本仓库源码为依据。

V2 的 godot.log 记录了 `info panel build`（第 3885 / 4632 行）、SkinChanger 停用 P3Makoto 的 76 个行为补丁（第 3888 / 4655 行），随后重建其他储君皮肤。后续切到其他角色时，临时修复记录 `alpha=0`、`有Deco=False`（第 3987—3999 行），并通过快照恢复到 1。这与玩家描述吻合。

本仓库的确切缺口：CharSelectInfo.Apply 隐藏原版介绍板后，原先只能在下一次 P3 的 SelectCharacter 后置补丁中恢复。一旦切换器清掉 P3InfoDeco 并停用补丁，该恢复入口就不再执行。只判断是不是 Regent 也无法覆盖同一储君内部换皮。

本次将原色快照的恢复绑定到 P3InfoDeco.TreeExiting，节点移除即可恢复，不依赖后续 Harmony 回调，也不依赖目标是不是 Regent。先撤销旧快照所有权，再恢复和移除节点；旧回调不能拆掉新面板。搭建或延迟构建失败同样恢复。只恢复本次实际改过的颜色，不递归强制全白。

## 奖励/火堆有些卡牌点不动：补上明确缺口，玩家根因尚未坐实

0.111 的奖励、升级和牌堆共用 NGridCardHolder 对象池。当前原版回收代码会断开外部点击事件，因此不能把此次报告直接归因于“旧点击事件必然残留”；0.14.56 已删除的 hitbox.MouseFilter 修改在当前版本也没有恢复。

本次只对 P3 实际借用的控件补充离场清理：解除牌堆的三个自定义鼠标事件，校验当前父节点和界面所有权，清除按下、悬停、内部焦点和悬停补间。目标是避免这些状态跟着对象池去奖励/升级界面；没有将所有牌强制设为可点击，没有更改鼠标过滤或原版选择条件。

另外可确认选牌动画兜底的实现缺口：原来只恢复 Visible，无法修复翻面时已经 Visible 但横向缩成 0.01、或仍透明的牌。现补齐缩放、透明度、位置恢复；完整/精简共用取消序号，旧发牌/压暗回调不能继续改下一轮卡牌。同步搭建失败立即恢复明牌，异步异常仍有显示兜底。正常演出流程和时长保持。

这些缺口已修，但本次没有收到卡牌点不动时的具体日志，也未重现，因此不能断言覆盖了玩家报告的全部情况。清理本身把握较高，根因对应关系仍不确定。
