# Codex 任务 prompt

这里是交给用户本机 Codex 的任务 prompt（每个文件一个会话）。写新 prompt 时遵守这些长期规则：

- **生图一律真透明底**（用户 2026-10-14）：RGBA，轮廓外 alpha = 0，不用绿幕 / 白底再抠图；自检里写明检查轮廓外 alpha、边缘无底色残留。
  全屏背景图除外，但叠在人物前面的前景层也要真透明。
- 手势、姿势照 P3R 原版截图严格描述（参考图放 art/parts_src/ref/ 等目录并在 prompt 里列出），写清自检条目。
- 安全清单原样保留：不改代码 / 已有资源、不改写历史、不 --force、不启动游戏、不读 obs.json 和密码、游戏文件只读、不绕过安全拒绝、意外情况停下报告。
- **编译 / 安装类任务不做实机验收**（用户 2026-10-19）：Codex 不启动游戏、不用 Computer Use，用户自己验收；build 文档里不写实机复验步骤。
- **发布时自动递增版本号**（用户 2026-10-23）：每次发布修改包由 Codex 自动递增补丁版本号，同步运行常量、模组清单、ZIP 文件名和版本记录，不再询问。用户明确指定版本号时以用户指定为准。
- 允许忽略的未跟踪目录（原样保留，不移动 / 删除 / 提交）：art/treasure_hands/、docs/qa/v0.14.69/、mod/_build/、mod_build/、art/p3menu_system/ref/menu_transition_frames_020-107/frames/，以及别的会话正在生成、还没提交的目录（例如 research/p3r_camp/）。
- git 命令都带 -c safe.directory=<repo>；fetch / push 带 HTTP/1.1 参数并按 5/10/20/40 秒重试；被拒绝先 fetch 再 merge --no-edit（不 rebase）。

## P5 Joker 姿势图：人物大小 / 比例一致（用户 2026-10-26 着重要求，长期有效）
同一个人物的所有姿势图，切换时头的大小、身体比例、站的位置不能跳。每次出新姿势图都必须：
1. **过渡帧 / 同一动作的后续帧，以已经定稿的那一张为底图做图像编辑**，只改需要动的部位（手臂、武器、衣摆、头发），身体、头的大小、肩宽、腿、脚的位置保持底图不变。3D 渲染、草图、原版关键帧**只当姿势参考**，不当底图（除非用户明确要求以它为底图，比如 gun_a2）。
2. **新动作的第一张关键帧**，以 art/p5/poses/idle_a3.png 为人物 / 比例输入。
3. **出图后、给用户看之前**，跑一致性检查：
   `python tools/p5/pose_consistency.py <底图名> <新图1> [<新图2> ...]`（文件名不带 .png，都在 art/p5/poses/）
   它会出一张并排对比图 check_<新图1>.png 并给每张打分；**有 FAIL（头的大小差超过 5%）就用底图重画那一张，不要手工缩放凑数**，最多重画 2 次，还不行再报告。报告里贴上检查输出。对比图不用提交（看完删掉）。
4. 通过后在 tools/p5/normalize_poses.py 的 POSES 表里加上新图（比例 1.0、对齐方式按动作选 rear / front / mid），跑一次，游戏用 art/p5/poses/final/ 下的版本。

## P5 Joker 动画不能跳（用户 2026-10-26，长期有效）
每个动作的相邻两帧变化都要小，跳就补过渡帧，帧数不限。标准用脚本量：
`python tools/p5/sequence_check.py <按播放顺序的帧名…>`（读 art/p5/poses/final/，所以要先把新图加进 tools/p5/normalize_poses.py 跑一次）
每一步给出：轮廓重合度（overlap）、脸移动了多少像素、两只脚各移动了多少像素。**overlap < 0.62 或脸移动 > 90px 判 JUMP**，那一步中间要补一张过渡帧（以前后两张里已定稿的那张为底图编辑，姿势取两者正中间，脚的位置也取中间），补完再跑，直到没有 JUMP。残影帧、受击第一帧这种本来就该突然的，用 --allow <帧名> 跳过。
收回待机的那段（攻击后、收枪后、召唤后）同样要检查，不能只顾出招那段。
