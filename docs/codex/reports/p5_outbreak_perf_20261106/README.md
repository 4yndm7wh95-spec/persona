# 毒性爆发捏碎后卡顿调查（2026-11-06）

## 结论

找到足以解释“每次捏碎后半段明显降帧”的主要瓶颈：巨手的两遍全屏体积渲染，在捏碎后的前顶、消散阶段需要约 21～23ms GPU 时间。此数字仅含巨手及简单底色，未计入游戏人物、碎片、毒焰和界面。75fps 的单帧预算为 13.33ms，60fps 为 16.67ms；巨手本身就超预算。

前后分层是在 0.9.11 增加的。为了让指节和拇指压住眼神横幅，同时让掌心在横幅后，两层各自执行了完整的手部计算，最后一行才用遮罩决定保留哪些像素。0.9.12 修复了它们的排序，没有减少这两遍运算。

## 独立实测

不启动游戏、不修改已安装 mod。使用本机普通 Godot 4.5.1，D3D12 / Forward+，同一张 RTX 4060 Laptop GPU。运行现有 C# 文件里的实际巨手、光圈和舞台 shader。测试 SubViewport 为 1920×1080，关闭垂直同步和帧率上限；每种条件先等待 24 帧，再采 72 帧。记录该 SubViewport 的 GPU 时间中位数与 P95。

第一轮 perf.gd 分开测单/双遍手、不同消散程度、五个光圈。第二轮 tail_perf.gd 使用生产代码的捏碎后姿态公式：FadeTime=0.45；前顶 0.06s；dissolve=OutCubic(k)；alpha=1-InCubic(k)。k 是这 0.45 秒尾段的归一化时间，取静态切片；不改变游戏代码。

| GPU 时间中位数，毫秒 | 原有两遍完整手 | 只算一遍完整手（定位对照） |
| --- | ---: | ---: |
| 捏碎刚开始，k=0 | 14.35 | 7.12 |
| 捏碎后 45ms，k=0.1 | 20.78 | 10.41 |
| 捏碎后 225ms，k=0.5 | 22.98 | 11.29 |
| 捏碎后 427.5ms，k=0.95 | 22.86 | 11.33 |
| 同样前顶的位置，关闭消散 | 19.25 | 9.41 |

同一轮单独五道光圈 0.16ms，单独红色舞台 0.21ms。可见这两项不是当前主要开销；不能据此排除与其他效果叠加时的额外成本。

## 为什么偏偏后半段更慢

1. 双遍重复：CrushHand.cs 创建 rear/front 两个全屏 ColorRect；各自最多执行 90 次表面寻找、64 次烟雾积分，以及轮廓火焰的额外表面寻找。hand_pass 的遮罩在整个 fragment 接近末尾才应用，不能节省前面的计算。单遍对照约减半，验证重复开销。
2. 镜头前顶：捏碎后手的 z 从 2.1 降到 1.75，画面覆盖变大。同一前顶位置即使关闭消散，两遍也要 19.25ms，比起始 14.35ms 更贵。
3. 烟雾消散：原先较实的手会使透过率 T 很快低于 0.02，提前结束积分；散成烟时更多射线要走得更深。叠加前顶后达到约 23ms。只把最终 alpha 降低不会省掉循环：第一轮 alpha=0 的控制也仍消耗约 22.6ms。
4. 同一拍还会生成横幅碎片、启动各目标的火焰/怨灵和伤害数字。这些会继续占预算；本轮没有给它们分别做完整 C# 时间轴 profiling，不能宣称巨手是唯一来源。
5. 代码另有设计性的约 80ms 命中顿帧。它解释捏碎那一下短停，不足以解释随后约 0.45 秒的持续降帧；出牌完成的日志没有显示 time scale 残留。

## 优化方向

保持用户认可的“掌心在后、指节在前”和现有图层顺序：
- 避免两层各自重复求整个体积。优先一次计算手的颜色/遮挡结果，前后层只做轻量合成；或在横幅已经隐藏之后取消尾段的重复遍，并核对碎片前后关系。
- 针对散烟阶段减少仍在计算的体积区域/步数，评估较低分辨率离屏渲染再放大，不牺牲指节抓纸的结构。
- 接近完全消失或完全不可见时直接停画，而不是让全屏 shader 计算完再乘零。
- 这几项完成后再测碎片创建峰值和多目标毒焰。不要先删除光圈或改变群伤结算，当前证据不支持它们是主因。

本轮为调查报告与可复现测量，不修改或安装新的 mod。离线场景不含完整游戏负载，表内值不能冒充实机整段 fps；但已经复现“后半段更贵”和“双遍接近翻倍”的关系。
