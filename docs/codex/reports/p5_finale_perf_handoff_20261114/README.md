## 问题证据与结论边界

用户反馈：华丽收场整段明显掉帧，重复出牌仍会出现，并非只有首次加载卡顿。

本地日志：游戏 0.111.0，P5Joker 0.9.28，RTX 4060 Laptop GPU，D3D12 / Forward+，2560×1440；图形设置 MSAA=8。多次 `GRAND_FINALE` 之后都有类似记录：

```text
health hitch 65ms gpu=64.1ms render_cpu=0.4ms p3=0.1ms
health hitch 64ms gpu=63.5ms render_cpu=0.4ms p3=0.1ms
```

首次另有约 1145 ms 的停顿；这里针对重复演出时的 GPU 成本。P3 的计时很小并不等于量到了全部 P5 CPU 开销，但 GPU 63–65.5 ms 的重复记录直接支持 GPU 瓶颈。

独立场景测试没有复现整场游戏的 65 ms 峰值，**不能确定全部峰值由某一个着色器或灯光造成**。MSAA 单项测试也不能解释该幅度，未修改全局图形设置。本次是有测量支持的局部渲染优化，完整实机效果仍待确认。

## 源码改动及移植意图

### `SinfulRender.cs`（新增）

- `Sky`：只把自绘夜空放入最大 1280×720 的独立 `SubViewport`，按比例限尺寸，再线性放大。着色器仍以完整屏幕 `sres` 计算场景位置，人物和平台保留原分辨率。夜空星点、月亮及燃烧边缘会略柔和。
- `LightActors`：为演员和撒旦耶尔子树临时加入 `1 << 19` 光照遮罩，保存原 mask，并在演出根节点退出时恢复。
- `Observe`：每次演出结束输出 `finale render-budget-v1` 的帧数、主视口 GPU 中位数/P95、最慢帧。只作定位数据。

### `SinfulShell.cs`

- 平台贴图存在时直接取样；跳过原本算完又被贴图颜色覆盖的岩石噪声。贴图透明区/范围外以及无贴图回退的完全透明区提前 `discard`。
- 用 `SinfulRender.Sky` 创建天空，其余人物、平台、动作、伤害时刻和演出结构保持原逻辑。
- 原有点光改为专用 `RangeItemCullMask`，照演员、撒旦耶尔和平台，避免同样的全屏灯光影响无关原场景、其他特效和 UI。
- 接入光照遮罩恢复和演出性能摘要。

### `SatanaelPuppet.cs`

- 读取角色贴图后，在 alpha 完全为零时 `discard`，跳过后续边缘取样、光照和溶解计算。当前轮廓逻辑只在有 alpha 的轮廓内部贡献颜色，故可跳过透明像素。
- 闪电强度 `strike <= 0` 时跳过闪电像素计算。

## 云端 Claude 的建议合并方式

先在你实际负责的最新开发分支审阅本说明和源码提交，再决定 cherry-pick 或逐段移植。不要用旧版整个文件覆盖已有的新功能。

```sh
git fetch origin codex/p5-finale-perf-handoff-20261114
git show --stat 5e5095c0
git show 5e5095c0 -- p5mod/src/Vfx/
# 在最新开发分支/工作树中确认差异后，仅取源码提交：
git cherry-pick 5e5095c0
```

如果开发分支已继续前进，尤其这两个原有文件又有改动，请按上面的优化意图逐段合并，保留新的坐标、灯光、动作、特效和版本号。若希望同时保留说明，可再合入本分支的文档提交。**不要把开发版本退回 0.9.28，也不要替换成本地历史 DLL。**

合并时需要重点复核：

1. 新版如果占用了光照 bit 19，选用未占用 bit；如果多段演出可以重叠或别的特效同时修改 mask，单纯保存/恢复原值可能互相覆盖，需要引用计数或统一生命周期管理。
2. 新演员或特效在 `LightActors` 遍历后动态加入时，不会自动取得专用 bit；按新版节点创建流程补入。检查提前结束战斗、切房间、跳出演出后 mask 是否恢复。
3. 新天空若开始依赖主视口 `SCREEN_UV`、读屏、主视口灯光或外部画布状态，不能直接放入目前的独立缓冲；保留完整屏幕坐标含义，检查宽屏、缩放和窗口大小变化。
4. 检查 `Fx.HoldClocks` 递归进入新 `SubViewport` 后的冻结/恢复，以及群蛇/毒雾和断崖交叉淡化；这些没有完整实机验收。
5. 新角色着色器若加入轮廓外发光或透明区采样贡献，重新判断 alpha=0 提前退出是否仍成立，不可机械套用。
6. 新摘要读取的是**主视口** GPU 时间，不包含天空子视口；且要求调用方已启用对应的 GPU 计时。本地 P3Mod 的监测启用了它，其他组合可能读到零。后续完善监测时应分别量两个视口，再解释总成本；不要用该主视口数值单独宣称完整提升。
7. 以目标支持的游戏版本重新编译；游戏内连续打出多次华丽收场，覆盖无能力、群蛇、毒雾及多个敌人，比较整段演出的 GPU 耗时和画面。确认完整效果再按开发流程升级版本、打包发布。
