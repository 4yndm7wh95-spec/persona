# 首次开抽牌堆：改掉同步 MSDF 路径，而非继续等待预热

基于热修复后实测：hero3d ready (dive ok)，Draw 首开 144.2ms，head=72.1、focus=33.8、tail=33.0；重开约 3.7ms。首开前中文预热没有运行。此前“拆批次并等鼠标静止”的方法无法保证即时首开顺畅。

## 找到的具体成本

游戏的 NotoSansCJKjp-Bold.otf 为 16,998,140 字节，其导入参数开启 multichannel_signed_distance_field，pixel_range=24、size=48。首次使用中文文本触发的 MSDF 生成不能靠异步读文件消除。

用独立 Godot 4.5.1 进程复现（无游戏、无预热）：原字体开启相同 MSDF 参数后，“抽牌顺序随机 · 按类型 → 费用排列”的 Label 入树/取最小尺寸耗时 97.259ms；“点击任意处返回”为 40.243ms。普通栅格化子集对应约 15.820ms、1.078ms。宽度一致；bitmap 与 MSDF 的行高可能略有差别，实机仍需检查排版。附件是当次原始输出，不是整套游戏的性能承诺。

## 修复

- 新增同源字体子集 P3PileUI-Bold.otf，352 个字符、约 174KB；保留固定文案、现有卡名和 ASCII。生成脚本逐字比较轮廓、水平度量与覆盖，无字形替换。字体族重命名并附 SIL OFL。
- 只有牌堆使用此小字体的普通字号栅格化；牌堆专用 Barlow 回退也改为此字体，避免间接加载完整 MSDF 字体。其他界面原字体不变。
- 罕见、外部模组或繁体卡名超出子集时，按需回退原字体，避免缺字；这类首遇文本仍可能触发原字体成本，不能保证未知文本恒定耗时。
- 特写层、升级按钮仅在首次选择特写时创建；悬停名牌仅在需要时创建。每次开牌堆不再为不可见内容支付初始化成本。新日志 perf pile focus prepare 单独监测首次特写，避免隐藏延迟转移。
- 去掉按全卡名字库生成约 250 个预热任务的做法，只保留固定文案，继续小批次且跨帧保留到真实绘制。普通小字体不再等待中文重初始化门槛；Spine 重任务仍按原条件执行。
- 不通过延迟打开、强制等预热、阻止点击或临时换语言来掩盖卡顿。

## 验证边界

代码 Release 构建及双版本兼容检查另附；独立引擎测试显示字体路径成本显著降低，实际游戏首次打开、首次悬停、首次特写及升级交互仍待实测，不能用组件测试代替用户体验结论。没有启动游戏。

复测应冷启动后直接读档并立即点击，不要求鼠标静止或停 5～10 秒。看 Draw build 的 head/focus/tail、focus prepare 及 hitch；同时检查中文、名牌、特写、升级、手柄返回、不同分辨率、未知名称回退。

本次保留空 CampTop 缩放轨修复。用户要求性能修复先完成，再合入并构建 v0.14.97；合并后必须确认小字体路径、惰性特写、批次调度与 CampTop 修复均未丢失。
