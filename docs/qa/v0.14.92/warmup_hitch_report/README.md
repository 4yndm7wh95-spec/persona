三项累计同步计时 1257.3ms（不是单个连续 1.257 秒停顿），末项附近还有 595ms hitch。`vfx_nodes=-1` 表示采样当时没有 NCombatRoom 实例，不足以确定具体可见页面。

## 对照代码后的推断

`PileFx.WarmText` 已按实际字号分成 5 份，但中文任务粒度仍过大：part 2 同次创建 19px、20px 两组中文标签；part 3、4 将 `CardFrameSkin.TitleChars` 各一半以 54px、6px 描边预热。这里字号实际乘 k。

`IdleWarmup.Step → WarmOne → PileFx.WarmText` 是主线程同步执行。后台预取字体文件只能减少文件读取等待，无法自动消除随后主线程调用引发的字体处理、排版、标签入树及潜在字形生成。当前计时覆盖整个 WarmOne，不能再细分到其中某个字体引擎函数；“全是字形栅格化”仍需 profiler 证据。

与前一版相比，主要开销已从点击时提前到预热时。仅延长任务间隔、等鼠标不动或再套后台读文件，都不能解决一次不可中断调用持续数百毫秒的问题。

## 建议优先级与实现方向

1. **优先缩小并细拆中文预热。** 固定文案按实际字符去重，按字体实例 / 实际字号 / 描边组合去重；特写牌名优先预热当前牌组可能展示的名称，新增牌名增量补齐。不要丢掉必要组合而让首开退化；语言和分辨率变化应有缓存失效策略。
2. **每任务只处理少量字符、一个字体组合。** 可以从每批 4～8 个字符起试，用实际耗时自适应缩小；这只是待测起始值。避免在一帧创建半份全部卡名字形的标签。每帧设 2～4ms 软预算，达到预算就把剩余任务留到以后；预算不能打断一次引擎调用，所以必须同时细拆任务。若单字仍超预算，需剖析字体首次初始化/回退或调整加载时机，不能靠外层预算掩盖。
3. **监测延迟到渲染阶段的成本。** 除小批次同步耗时，还记录后续帧 dt / hitch、批字符数、字体来源、字号、描边、队列进度。标签创建计时很短并不保证当帧绘制无阻塞；预热节点应在实际绘制后再回收。
4. **先保障可见 UI，再处理隐藏特写。** 对非必需的特写牌名字形，采用增量预热；必要时分批准备或复用隐藏特写节点，确保第一次真正点开特写也有测量。UI 缓存属于后续可选改动：本次复开已约 3ms，不应优先为它增加复杂度。
5. **让调度避开交互和动画。** 选人、出牌、转场期间暂停重任务；优先利用已有加载界面，并持续保留小批次预算。仅“鼠标静止”不是安全条件，画面可能仍在动画。不要把节点创建或未经确认线程安全的字体/渲染操作直接移到 Task.Run；后台限于确认安全的数据读取解析。

建议先实施 1～3，再对照测试决定是否需要 4～5 的额外结构改动。暂不建议优先重写 3D 舞台。

## 验收方式（建议目标，不是已达成结果）

- 同设备、同分辨率、同语言分别测试冷启动、读档直入战斗、新局进地图后战斗；还需测首次特写、首次弃牌堆、切换分辨率/语言后的首次打开。
- 记录完整预热周期内批次和帧时间的最大值、P95/P99，以及 >50ms hitch 的上下文；不要只看整批总时长。
- 首先消除这类可归因于中文预热的 200～600ms 停顿；2～4ms 为主线程小批次软目标，最终阈值应结合实测确定。
- 同时保持 Draw 首开接近本次约 13ms、重复打开约 3～4ms，不通过跳过必要预热把卡顿推迟到点击或第一次特写。
- 测试前后保留 perf pile 分段、预热完成状态和错误记录。不要把其他模组启动错误或未归因的 hitch 都算作本功能。
