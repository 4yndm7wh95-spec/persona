## 文件与生成方法

- A：`style_A_p5r_official_1.png`、`style_A_p5r_official_2.png`，大块黑影、锐利明暗边缘、细墨线。
- B：`style_B_anime_1.png`、`style_B_anime_2.png`，现代动画赛璐璐、较柔和的深灰层次。
- C：`style_C_sts2_blend_1.png`、`style_C_sts2_blend_2.png`，较粗深色轮廓和衣服上的绘画纹理。
- [compare.png](compare.png)：第一行 A_1/B_1/C_1，第二行 A_2/B_2/C_2。每张完整缩为 512×768，文件名在下方。棋盘格仅用于对照预览，不是六张候选图的背景，也未写回候选图。

使用内置 **image_gen**，不是 CLI/API 回退。共 6 次独立调用，每个候选一次；每次都以两张指定本地参考图作为输入并设 `transparent_background=true`：

1. `art/p5/ref/joker_nomask_ref.jpg` 只用于无面具面容、发型和身份，不把其红底、手势或画风当约束。
2. `art/p5/ref/joker_thief_nomask_3d.png` 用于黑色长大衣、灰马甲、白口袋巾、红手套、深色长裤、棕色短靴等服装细节。

六份完整最终提示词、输入参考角色、本机生成来源路径、目标路径和 SHA-256 都保存在 [prompts.json](prompts.json)。提示词明确要求 1024×1536、全身、四周至少 60px（多次强调 80px）、朝右 3/4、远手插袋/近臂下垂、双腿分开、无武器、无文字/阴影/光晕和真实 alpha。

**六张候选均逐字节复制生成原 PNG，SHA-256 与工具输出一致。没有裁剪、抠图、清 alpha、补边、改色、缩放或重新编码候选原图。** 只有 compare.png 按任务要求缩图拼接。没有使用绿幕：工具已返回 RGBA，不属于工具完全不支持透明输出的情形。

## 透明与留白的检查口径

所有原图尺寸均为 1024×1536 RGBA，alpha 范围为 0～254；人物间隙和大部分外部背景能透明。不能只用“四角透明”判断全部外部 alpha 为 0：B_2、C_1 在 (0,0) 就有 alpha=1，其余文件也有远离主体的低 alpha 残点。

[alpha_audit.json](alpha_audit.json) 保存每图 alpha 包围范围、60px 外框残点数、像素样本及来源哈希。为避免把正常的抗锯齿边缘误当大块背景，额外检查 alpha≥128 的近似主体向外膨胀 16px 后，剩余非零像素：六图仍有残点，**最大 alpha 均仅为 1/255**。因此视觉影响很轻，但严格“轮廓外 alpha 全为 0”没有通过。工具黑底预览中可见的灰/红晕不能直接当作同等强度的实际背景；棋盘 alpha 合成后没有大块实底。未见绿幕或白底污染，但不能把低 alpha 残点当作已完全合格的透明边缘。

以下主体留白按 alpha≥128 包围框近似计算，顺序是左/上/右/下（px）；这不是原图修边，也不代替精确人工轮廓。全 alpha 包围框及数值原样保留在 JSON 中。A_2 主体留白达到 60px，其余五张主体完整但上下留白不足。若把全部低 alpha 残点也计入，六张均不满足严格的 60px 完全透明外框。

## 保存、限制和交付

六图均为 1024×1536 生成原图。没有在用户挑母版前擅自选择或优化其中一张。六次生成均成功返回图像，**拒绝 0 次**，没有绕过安全拒绝，也没有换工具、模型或 API 重试。

提示词强调留白/透明约束后，工具仍返回上述偏差；任务要求每个画风两张并原样提交，因此本轮保留这六个结果与失败项，不把它们称为完全合格母版。用户可先挑画风，后续再明确处理所选母版的构图/透明边缘和手部。

只提交 `art/p5/concept`；不会纳入 art/cards 的已修改文件，也未 stash 或还原它们。没有修改 mod、现有资源、游戏文件或 Git 历史，没有启动游戏或使用 Computer Use。

为便于复核，六份提示词及 SHA-256 在 prompts.json，alpha 数值在 alpha_audit.json；候选原图未被脚本改写。拼表是独立预览，格子背景不属于源文件。
